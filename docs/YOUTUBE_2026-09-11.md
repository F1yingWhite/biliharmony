# YouTube 接入记录（2026-09-11）

## 当前实现

- **YouTube 与哔哩哔哩是同级平台，不再是底部 Dock 的第 4 个 Tab。** 入口在「我的」页
  分组里的 `YouTube` 行；切入后由 YouTube 自己的外壳接管整个页面（自带玻璃头栏与
  底部 Dock：探索 / 搜索 / 我的），回程在 YouTube「我的」页的 `哔哩哔哩` 行。
  平台状态由 `common/PlatformStore.ets` 唯一持有并持久化（键 `platform`），
  主框架里原有的两处 `currentTab !== 3` 魔数已随之删除。
- Dock 里的 Tab 名称用**探索**而非「首页」：YouTube 推荐流需要登录，用一个不存在的
  首页去伪装推荐是不诚实的，探索页只做公开可得的分类检索。
- 搜索读取 YouTube 公开网页的结构化数据，无需 API Key；目前展示首批普通视频结果，
  不含 Shorts 专属列表和后续分页。
- 支持 watch / youtu.be / shorts / live 链接和 11 位视频 ID；在搜索框粘贴链接会直接进详情。
- 详情读取公开视频标题、作者、观看次数、日期和简介；匿名播放器接口要求登录时，仍尝试读取公开 watch 页面元数据。
- ArkWeb 承载官方 IFrame Player。应用标识作为 base URL / origin，保留 YouTube 控件，提供加载失败、嵌入限制提示、重试及外部打开。
- 全屏进出和返回键联动；退后台暂停，离页释放播放器，播放状态控制常亮。
- YouTube 视频模型、页面解析与播放器独立，不复用 B 站 aid/bvid/cid 或登录凭据。

## 与哔哩哔哩的视觉一致性

用户明确要求两个平台观感一致，因此 YouTube 侧的样式不是另起一套，而是照抄哔哩哔哩的
既有规格（改样式时两边必须同步改）：

| 部件 | 规格来源 | YouTube 侧取值 |
| --- | --- | --- |
| 头栏光感层 | `components/GlassHeaderBar.ets` | 同一渐变、`linearGradientBlur(28)`、高度 `statusBarInset + 44` |
| 头栏淡出 | 同上 | `1 - fade / 0.85` 与 `translate y = -8 * fade` 逐参数一致 |
| 搜索胶囊 | 同上 | 高 36 / 圆角 18 / 0.7 描边 / 文字 13 号 `#777B85` |
| 信息流卡片 | `components/video/VideoCard.ets` 的 `homeStyle` 分支 | 白色容器 + 圆角 16 + 阴影 8 + 按压缩放 0.9 |
| 封面 | `components/FeedCardParts.ets` | 4:3、底部 40 渐变 `#A6000000`、渐变行高 32 |
| 标题 | 同上 | 14 号 / 行高 19 / Medium / 两行截断 / 高 50 / 左右 12 |
| 作者行 | `VideoCard` 底栏 | 高 32 / 左右 12 / 文字 11 号 `#7D8490` |
| 分组卡片 | `views/MineView.ets` 的 `groupBg()` | `#26272B`(深) / `#FFFFFF`(浅)、圆角 12 |
| 网格与内缩 | `common/LayoutTokens.ets` | `feedColumns()` 响应式列数、`feedGap` = 7、`feedMaxWidth` |

因此 `YouTubeView.ets` 不引入任何新的设计常量，只从上述来源取值。两个平台唯一的设计差异
是强调色：哔哩哔哩侧沿用主题 `accentColor`，YouTube 侧用 YouTube 红 `AppTheme.DANGER`
（Dock 选中态、搜索按钮），这是刻意的品牌区分，不是不一致。

## 两个已定性的外部约束

### 1. 公开页面必须声明桌面版 User-Agent

不带 `User-Agent` 请求时 YouTube 会返回验证页或移动版页面，`ytInitialData` 里没有
`videoRenderer`，搜索解析整体失败（旧实现会抛「页面格式已变化」）。
2026-09-11 在本机走代理对同一 URL 实测：

| User-Agent | `parseSearch` 结果 |
| --- | --- |
| 桌面 Chrome | 22 条，标题/频道/时长/观看数全部解析正确 |
| 移动 Chrome | 抛错「返回了验证页或页面格式已变化」 |

因此 `YouTubeApi.DESKTOP_UA` 是**必需**的兼容性声明，不是伪装登录态。
回归测试 `YouTube: public pages are requested as a desktop client...` 锁定该行为。

### 2. ArkWeb 内的播放器不共享应用的代理配置

`HttpClient` 的 `usingProxy` 只作用于 `@ohos.net.http`。ArkWeb 里的 Chromium 是独立
网络栈，默认走**系统代理**；本环境模拟器无系统代理参数
（`persist.net.http.proxy`、`persist.net.proxy.host` 均不存在），且模拟器本身
无法到达 YouTube（对 `www.youtube.com` 100% 丢包，对 `www.baidu.com` 正常）。

**2026-09-11 Mac 侧更正（上面这段的结论是错的）**：给 ArkWeb 下发代理的 API 是
`webview.ProxyController.applyProxyOverride(config, callback)`（API 15+，
`static` 挂在 **`ProxyController`** 上）。`ProxyConfig` 只是承载代理规则的参数对象，
自己**没有**这个方法，照它写才会得到
`Property 'applyProxyOverride' does not exist on type 'typeof ProxyConfig'`——
那是**类名写错**，不是「SDK 类型索引取不到」。改用正确类名后，同一台 Mac 的 API 26 SDK
编译与运行都成功（日志 `ArkWeb proxy override applied`）。

实现见 `services/network/WebProxy.ets`：沿用同一个 `netProxy` 启动参数，
归一成 `scheme://host:port` 后 `insertProxyRule`，**默认空值完全不调用 ArkWeb 接口**。

另外，播放器停在 `about:blank` 的**直接原因并不是网络**，而是初始 `about:blank` 导航
把 `loadData` 的文档 abort 掉了（`ERR_ABORTED url:data:text/***`）——两个问题同时存在，
只修网络仍然是空白。详见 `docs/ArkUI易错清单.md` 第 18a / 18c 条。

## 账号范围与尚未完成项

用户需要同时同步订阅/播放列表，以及在播放器中使用登录账号或 Premium 权益；目前这两项均未接入。用户尚无 Google Cloud 项目或 OAuth 客户端，需要从头配置。

1. 没有查到出境易向其他鸿蒙应用公开共享 Google 账号会话的 SDK/API。官网的账号管理说明不能作为跨应用共享授权的证据。
2. Google Data API 的用户数据授权需要应用自己的 OAuth 配置。应使用外部浏览器授权；不能在受应用控制的 WebView 里完成 Google OAuth，也不能把鸿蒙手机冒充桌面设备或电视来选客户端类型。
3. OAuth access token 用于 API 授权，不是 YouTube 网页登录 Cookie。IFrame Player 没有传入 OAuth token 即可登录或启用 Premium 的接口。账号数据授权与播放器会话必须分别验证。
4. 在确定可用的鸿蒙回调方案和播放器登录方式前，不创建无法闭环的登录按钮，也不导出出境易 Cookie、账号数据库或密码。YouTube「我的」页因此只做说明与「了解如何连接」弹层，账号能力行（观看历史/稍后观看/订阅内容/播放列表）显示为未解锁。
5. 公开页面格式可能变化；当前实现显式报错而不执行远端脚本。后续可在获得配置后使用官方 Data API 替代网页解析。
6. 本次不包含 YouTube 下载、订阅操作、评论、上传或后台音频。
7. ~~**搜索分页未实现**~~（2026-09-11 已接入）：网页端翻页走 InnerTube continuation，
   即向 `youtubei/v1/search?key=<页面下发的 INNERTUBE_API_KEY>` POST
   `{context:{client:{clientName:"WEB",clientVersion:<INNERTUBE_CLIENT_VERSION>,hl:"zh-CN"}},continuation:<token>}`，
   从 `onResponseReceivedCommands[].appendContinuationItemsAction.continuationItems` 取新视频与下一个 token
   （旧版 `continuationContents.sectionListContinuation` 也兼容）。token 由上一页携带，
   取不到 InnerTube 配置时**直接停止翻页**而不是猜一个请求；触底自动加载，失败保留已有结果并在底部重试。
   实测：单页 20 条，请求体与请求头由回归测试锁定（桌面 UA、`Content-Type: application/json`、不带任何 B 站凭证）。

### 可选代理配置（默认关闭）

`HttpClient` 支持可选的 HTTP 代理，用于网络受限环境下访问 YouTube。
**默认空值，不配置时行为与历史版本逐字节一致**（不下发 `usingProxy`）：

```bash
hdc rport tcp:7897 tcp:7897
hdc shell aa start -a EntryAbility -b com.piliplus.harmony --ps netProxy http://127.0.0.1:7897
```

注意它只覆盖应用自身的 HTTP 请求（搜索与详情元数据），**不覆盖 ArkWeb 播放器**。
