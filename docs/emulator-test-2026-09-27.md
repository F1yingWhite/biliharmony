## 本轮结果

### 首页频道刷新与错误恢复（09:56—10:01）

- 推荐、热门、直播分别持有刷新/分页状态及操作序号。一个频道完成不会结束另一个频道的提示，旧刷新完成不会提前结束较新的刷新。刷新期间同频道不再触发分页。
- 热门/直播支持刷新覆盖正在进行的分页，并通过请求 epoch 丢弃旧响应；只有成功响应推进游标。离开组件时失效所有请求并清理显示状态。
- 热门/直播接口失败或响应缺少列表时抛出失败，成功空数组仍作为空数据处理。失败保留已有列表和游标，列表底部显示点击重试；重试区分刷新第一页与继续分页。
- 刷新提示只依赖当前频道的实际请求状态，不再由可能滞后的系统 Refresh 回调延长显示。
- 250 项回归测试通过，新增覆盖跨频道活动、刷新覆盖分页、两次刷新乱序、失败游标与重试模式、接口错误/空数据区分、页面退出后的响应隔离。完整 assembleHap 成功并已安装到模拟器。

## 已修复并安装

`services/network/HttpClient.ets` 原来仅接受小写 `set-cookie` 字符串。现增加：

- SDK `HttpResponse.cookies` 独立字段。
- 不区分大小写的 Set-Cookie 头，以及多个头的数组形式。
- 换行及无空格逗号分隔的 Cookie，保留 Expires 日期中的逗号。
- 仍仅接受可信主机和当前会话的响应，旧请求、第三方响应不能写入凭证。

该缺口与扫码失败路径相关，但未捕获用户当次授权响应的实际结构，因此不声称已证明唯一根因或扫码已恢复。

新增测试覆盖三种 HTTP 请求入口及会话/主机边界，**235 项回归全部通过**。DevEco 自带 Node 下 `assembleHap` **完整成功（包括签名）**，本轮生成并向模拟器覆盖安装 `entry-default-unsigned.hap`，安装成功后再次确认登录保持。

- 本地记录新增 cid 和 epId；同一视频切换分 P 会立即保存，不受上一分 P 的 15 秒节流影响。旧格式记录继续兼容。
