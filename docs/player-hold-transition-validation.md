# 长按倍速切换验证记录

2026-10-09，按用户要求，后续运行验证只使用鸿蒙虚拟机；没有再次操作真机。

## 修复和验证对象

长按与松手会改变全局速度，但音频队列内仍有旧速度生成的 PCM。
旧内核用最新速度解释整个队列，导致视频先等待、恢复速度后又追帧。
`tool/mpv/patches/0001-ohaudio-pcm-timeline.patch` 按各段 PCM 的实际媒体时长
计算音频位置和视频截止时间，同时将系统绝对单调时间换算到 mpv 的相对时钟。
音调校正滤镜常驻，重复倍速命令和确认事件也已合并。

测试采用同一应用代码、同一虚拟机和片源 `BV1R1e4zKEh1`，登录状态为游客。
虚拟机为 Mate 80 Pro Max、HarmonyOS 7 / API 26、x86_64、1320×2848。
两版均包含独立的 OHCodec 初始化失败清理修复 `0002`；基线排除 `0001`。
虚拟机缺少硬解所需的 GL 扩展，测试实际使用软件解码与 `vo=gpu`。
两版还使用相同的、仅存在于 QA 源码中的 GLES 纹理探测保护；ARM 构建没有此保护。

最终无底层诊断日志的虚拟机 HAP：`.qa/mpv-speed-core/vm-release-signed.hap`。
HAP SHA-256 为 `98da33d63b4260f3ad69ce5f8a902a570677fb2b0f817cd6ec2b681fb4f36dcd`；
其中 `libmpv.so` 为 `45860b5c58b0fb01c2eaf5acde7312c69f35d797757e396f5e58ac58873c8ab8`。
诊断包与最终包使用相同业务代码，底层 `BiliPcmTiming` 日志已从最终核心移除。

## 对照结果

| 观测 | 基线 / 未生效映射 | 最终无诊断包 |
| --- | --- | --- |
| 长按开始后相同播放位置的连续观测时长 | 94～192 ms | 31 ms |
| 松手后单次观测的最大媒体位置跳变 | 300～401 ms | 67 ms |
| 松手窗口最大音画差 | 255～338 ms | 38～54 ms |
| 两轮切换中的视频 Surface 最大提交间隔 | 298.462 ms | 68.020 ms |
| 两轮切换中的超过 80 ms 提交间隔 | 2 次，276.777 / 298.462 ms | 0 次 |
| 每个切换窗口新增内核掉帧 | 最高 11 帧 | 0 帧 |

时钟指标来自 30 ms 原生属性观测，连续相同位置的时长是观测下界，不能当作精确帧间隔。
Surface 指标来自 `playerSurfaceSurface fps`，只统计视频缓冲区提交记录，排除应用界面 FPS。
虚拟机没有提供这些缓冲区的最终呈现时间，不能把提交记录描述成面板逐帧呈现测量。
本片源的正常帧间隔、两倍速时的显示帧选择、虚拟机音频节律仍会反映在这些指标中。

最终包从 0 开始播放：首个非零媒体位置在约 151 ms 被观测到，首个 1.2 秒观测窗口推进到 968 ms。
持续 10 秒长按时，稳定区间约 5.04 秒推进 9.61 秒媒体时间；回到普通速度后正常推进。
诊断包另验证了拖回 0、暂停约 30 秒后恢复、三次短长按与快速松手；各切换窗口没有新增掉帧，
最大音画差约 30～49 ms。没有通过 seek、暂停、丢音频或缩小音频缓冲伪装倍速切换。

## 中间失败与边界

最初 PCM 补丁的时间戳直接比较了两个时基，映射没有启用；纯 C 单元测试通过不能说明此桥接正确。
加入换算后的一次早期冷启动曾出现约 1.2～1.5 秒供数间隔与慢播放。
随后增加耗时观测，同一逻辑的重复播放中查询约 0.16～0.33 ms、读 PCM 约 0.05 ms，
没有证实音频查询 IPC 阻塞。最终无诊断包的冷启动和后续切换未复现该次慢播放；
此记录保留该失败，不能据此声称已经验证所有音频设备、路由或虚拟机负载。

真正执行的纯 C fixture 共 6 项，覆盖混合速度队列、视频截止时间、静音尾部、暂停/恢复、重置、
未知 PTS、容量回退与跨时基换算。Windows DLL 由 OHOS LLVM 构建并经 Python ctypes 执行，未跳过。
固定源码、补丁、Windows 重建脚本、原始依赖库载体和 ELF/签名包校验都有对应记录。
ARM 核心使用相同补丁，完成编译、符号解析和签名包检查；这不等于已经运行验证 ARM 硬解路径。

## 复验入口

安装最终虚拟机包后打开上述片源，等待普通播放稳定，再重复长按 / 松手，并测试暂停、进度拖动和恢复。
用 HDC 的 `uinput -T -d 660 430 -i 2000 -u 660 430 -i 1800` 可在该竖屏布局复现一轮操作。
视频 Surface 记录通过 `hidumper -s RenderService -a "playerSurfaceSurface fpsClear"` 清空、
`hidumper -s RenderService -a "playerSurfaceSurface fps"` 读取；不能用整个窗口 FPS 代替。

本次原始日志位于忽略目录 `.qa/hold-transition/`：`vm-baseline-rates.log`、
`vm-unfixed-frames.txt`、`vm-release-rates.log`、`vm-release-frames.txt`、
`vm-release-long-hold.log`、`vm-rapid-rates.log` 和各自的指标 JSON。
这些日志只保留时间、速度、颜色和计数，不需要输出签名媒体地址。
HDR 的输入与输出结论另见 [播放器复用文档](player-core-reuse.md#hdr-选源与输出验证)。
