# 播放器跳转与双轨同步修复

日期：2026-09-15

## 源码中定位的问题

- `pause()` 尚未完成就调用 `seek()`，迟到的暂停可能干扰定位或恢复。
- 双轨定位完成后视频先播放，音频又定位一次；音频等待期间视频仍推进。
- 视频进入缓冲时，只暂停了弹幕，独立音轨可能继续播放。
- 跳转期间的旧 `timeUpdate` 仍更新弹幕、字幕、播放进度和自动跳过逻辑。
- 音轨 900ms 未回调就无条件视为完成；关键帧恢复仍按请求位置过滤实际落点。

## 修改

`PlayerSeekController` 等待双轨暂停，并在等待期间合并最新目标。取消操作会废弃迟到的异步结果。定位完成后成对启动两轨，去掉重复音轨定位。起播发现两轨错开也交给同一状态机处理。

视频缓冲时静音并暂停音轨，缓冲结束后重新成对定位。跳转锁定期间忽略旧进度事件。连续三个采样偏差超过 350ms 才纠偏，纠偏间隔至少三秒，避免一次回调抖动导致跳转。关键帧恢复按视频实际落点重新对齐音轨。音轨缺少回调时仅在播放头距目标不超过 150ms 时放行，否则继续等待原有超时恢复。

本轮保留工作区已有的请求调度等未提交改动，签名配置仍为 skip-worktree。
